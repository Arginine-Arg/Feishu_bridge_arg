# v1.24.0

## Magpie as a provider source

Subagents can now read providers from a local Magpie gateway instead of
cc-switch. `arg-bridge settings` asks which source to use when both are
available. Magpie keeps the API keys; Bridge only stores the gateway address
and the selected provider/model.

## One catalog for models and routers

`/model`, `/config` and `arg-bridge settings` list three sources together:

- models discovered from local cc-switch accounts;
- models exposed by Magpie;
- Magpie routing groups (`group/<name>`).

A routing group is a single selectable entry. Magpie switches among its
members by its own rules, so a primary failure can fall back without changing
the session. The main session and subagents can choose different entries.

Read-only `/btw`, writable workers and the reviewer share the selected
provider/model order. The writable switch only controls permission.

## Safety

- A Magpie entry requires Codex to be connected to the Magpie gateway.
  Settings checks the active `model_provider` and warns when it is not
  `magpie`.
- A dead gateway, missing provider file or empty model list is reported
  instead of silently falling back to another source.
- cc-switch and Magpie catalogs are best-effort: one broken source adds a
  notice and the rest of the list stays usable.
- The Broker route keeps the gateway base URL, `MAGPIE_API_KEY` placeholder
  and `source=magpie`; no key is written to the profile or Broker config.
