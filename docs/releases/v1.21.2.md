# arg-bridge v1.21.2

Fixes provider recovery leaking its internal `continue` nudge into Feishu as
visible assistant text. Version 1.21.0 sent the correct Codex `turn/steer`
request but also emitted a normal text event containing `continue`; the bot
therefore displayed repeated `continue` messages while Codex was reconnecting.

Recovery now:

- sends `continue` only as input to the active Codex turn with `turn/steer`;
- starts a private Codex continuation turn only after the previous turn is
  confirmed terminal;
- writes no `continue` text event, card update or standalone Feishu message;
- keeps the existing `/recover off`, `/recover on`, `/recover status` and
  `/stop` behavior;
- retains the oversized-history adoption fix from 1.21.1.

Regression tests cover continuous same-turn nudges, terminal continuations and
re-enabled recovery. Each case asserts that the user-visible event stream does
not contain a `continue` text delta.

Update each installed profile, then restart it:

```bash
curl -fsSL https://github.com/Arginine-Arg/Feishu_bridge_arg/releases/download/v1.21.2/install-global.sh | sh -s -- --version 1.21.2
hash -r
arg-bridge --version
arg-bridge restart --profile codex
```

Use `/recover status` to confirm the current conversation setting. If an older
bridge is still running while retrying, `/recover off` immediately stops new
recovery nudges until the profile is restarted on 1.21.2.
