# arg-bridge v1.16.2

Fixes `/codex 1` being rejected in structured sessions when the visible menu
belongs only to the native Codex TUI, such as:

```text
Giving this request a little extra thought
› 1. Dismiss and keep waiting
  2. Learn more
```

This informational popup does not pause the model or require an answer.
Codex keeps waiting and closes it when the response is ready. You may leave
it alone, or select it from Feishu while it is visible:

```text
/codex 1
/codex 2
/codex down enter
/codex enter
/codex esc
```

Pending structured model/approval/question requests keep using the App Server
protocol. A numeric choice follows the main or side session that owns the
request; if both have pending requests, use the matching card or
`/answer <request-id> <value>`.

For a TUI-only menu, the bridge validates the exact native thread and pane,
reads the current viewport (never historical scrollback), and rechecks the
menu immediately before sending navigation keys. A numeric choice navigates
to and confirms one visible option. Closed or changed menus, invalid numbers,
unbound panes and ordinary text are rejected. Controls do not start a new
model turn or interrupt the main task.

Saved external pane bindings and managed view identities continue to work
after updating and restarting the bot. No new native/adopt operation is needed.
TUI menu controls require a live bound native Codex terminal; a headless
structured session still uses its protocol cards and `/answer` commands.

Validation includes main/side protocol ownership, ambiguous requests, menu
closure/replacement races, invalid input, and a real tmux process that handles
the wait popup after adapter recreation without an App Server connection.
