# arg-bridge v1.18.0

Fixes long-running `/btw` and MixAgents subagent sessions that appeared to stop
forwarding progress even though the worker might still be running.

The previous `events-v1` path waited only on progress events while the event
stream was healthy. A quiet or stale stream could therefore hide a completed
terminal mailbox until the full wait window expired. Bridge now performs a
read-only `list_agents` reconciliation every 15 seconds and returns the
authoritative completed, failed, interrupted or not-found state immediately.

Liveness reporting now has two layers:

- the existing 15-second heartbeat remains active if the backend call itself
  stalls;
- at least every 60 seconds, Bridge emits the real Broker status and event
  cursor while the worker is running.

Codex reasoning summaries (`item/reasoning/summaryTextDelta`) are now exposed as
bounded progress. They are redacted, throttled and excluded from the final
answer text. Raw reasoning deltas, tool arguments, command strings, command
output and file contents remain outside the progress API.

The terminal `wait_agent` mailbox remains authoritative. Bridge automatically
continues across wait windows, reads from the persisted cursor, and avoids
duplicating the final result.

No side migration or `/btw out` is required. Update, restart each bot profile,
and an existing retained side can be checked with `/btw result`. A worker that
is genuinely still running will keep receiving the new status/heartbeat path.

Local validation: 1,228 ArgBridge tests passed, 12 environment-dependent tests
skipped, and all 28 vendored Broker tests passed. Type checking, production
build and isolated tarball installation passed.
