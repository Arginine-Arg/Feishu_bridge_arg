# arg-bridge v1.4.0

本版在 v1.3.0 结构化后端基础上增加动态 tmux pane 发现与绑定。

## 动态 tmux 会话

- 结构化 Codex pane 的身份从进程参数识别：`--remote <endpoint> resume <threadId>`。
- Bridge 不读取屏幕文字来猜测 session，也不会因为 pane 切换而重复启动模型任务。
- 在同一个 Bridge 托管 tmux session 中关闭旧 pane、打开新 pane 并执行结构化 Codex resume 后，下一条消息会自动绑定当前 active pane。
- `/tmux list` 显示可识别的 thread、endpoint 和 pane id。
- `/tmux bind <编号|pane id|socket::pane id>` 可显式绑定；绑定前验证 socket 所有者、App Server 和 thread 已加载。
- `/tmux unbind` 解除绑定并禁用该 scope 的自动重新发现，避免用户明确解绑后被立即重新接管。
- `/tmux status`、`/tmux tail`、`/stop` 均使用当前绑定 pane 对应的 thread。
- 重启后绑定映射保存在 profile 的结构化状态目录中，不会启动第二个 App Server。

## 安全边界与限制

- 只接受当前用户拥有的本机 Unix App Server socket；普通 `codex resume`（没有 `--remote`）不属于结构化后端，不会被误接管。
- 自动发现要求新 pane 位于原 Bridge 托管 tmux session；完全无关的 tmux server 需要显式 `/tmux bind`，并且仍需通过 workspace 和 App Server 校验。
- Claude 的官方 SDK 没有等价的本地 App Server attach 协议，本版继续拒绝把任意 Claude pane 当作结构化输入端；Claude 结构化会话仍由 Bridge 自己持有。
- 如果在同一个 Codex TUI 内使用内部 `/resume` 而不创建新的 `codex --remote ... resume` 进程，进程参数不会变化；请使用新 pane 或显式 `/tmux bind` 触发重新识别。

默认后端仍是 `terminal`，升级不会自动迁移旧 tmux 会话。结构化后端仍需在 profile 中设置：

```json
{
  "agentTransport": "structured",
  "structuredNativeView": true
}
```
