# arg-bridge v1.19.0

Recovers Codex main sessions from temporary provider errors and fixes structured
Feishu replies freezing after the first few characters.

Default recovery waits 30/60/120 seconds after a confirmed failed turn, with at
most three continuations. When Codex reports API reconnection and produces no
new text or tool activity for 60 seconds, Bridge interrupts that exact turn,
waits for terminal confirmation, then continues after five seconds. It does not
wait for all five native reconnection attempts to exhaust. User stops and
paused goals cancel recovery. Authentication, exhausted quota, budget, context
and sandbox errors are not retried. `settings` supports all providers, selected
provider IDs, or disabling recovery.

Structured card and markdown replies now use coalesced full snapshots with
acknowledged Feishu PATCH results. A rejected card can be rebuilt once; final
delivery failure triggers a complete fresh reply. Final Codex items reconcile
message drafts, including rewritten text and missing streamed suffixes.

Update and restart each profile. No native re-adopt is required for an existing
bound structured main thread. Recovery requires the bot to be subscribed to
the thread; restart can restore an unambiguous already-loaded saved thread.
MixAgents workers and terminal-only sessions retain their existing lifecycle.

Validation includes fault-injection tests for retry timing, stop races,
provider filtering, full-text delivery and Feishu rejection; a real Codex App
Server with a local failing API verified interruption, same-thread continuation
and complete text recovery. Full platform and installation checks run in CI.
