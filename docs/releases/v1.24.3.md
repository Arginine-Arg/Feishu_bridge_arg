# v1.24.3

## Re-opening a TUI refreshes the catalog

Codex reads `model_catalog_json` once at App Server start. Re-attaching to an
old server therefore kept an old model list even after Magpie rewrote the
catalog.

`arg-bridge native` now compares the catalog file's mtime with the target
server's start time. When the catalog is newer and the thread is idle, it
reclaims the stale server and starts a fresh one before resuming. The new
server reads the current catalog.

If the idle handoff cannot complete (another writer, a loaded sibling thread,
or a failed probe), the old server is kept and the TUI still opens with the
old list.

## Verification

- Unit tests cover stale, fresh and unconfigured catalogs.
- Existing native history and idle-probe tests remain green.
