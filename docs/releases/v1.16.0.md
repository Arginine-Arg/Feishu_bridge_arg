# arg-bridge v1.16.0

Settings can now configure the model version and reasoning effort used by
Broker subagents, including `/btw`, automatic workers and reviewers.

Run `arg-bridge settings --profile codex`, choose a cc-switch provider, then
choose a model and reasoning effort. The model menu reads the selected
provider's `settings_config.config` default model and same-provider TOML
profiles, plus explicit `models`, `availableModels` or `available_models`
lists in its settings config. A list entry may be a model ID or an object
with `id`/`model`. You can also enter a model ID manually or follow the
provider's configuration at dispatch time.

Model/effort preferences are stored by cc-switch provider ID. Switching from
A to B uses B's preferences or defaults; returning to A restores A's
preferences. The main session and cc-switch configuration are unchanged.
Configured provider preferences take precedence over the legacy
`sideReasoningEffort` setting. Existing profiles without preferences retain
their previous behavior.

The menu lists local declarations, not a verified server model catalog.
Support for a model or reasoning level depends on the provider. Manual
Broker routes and local Codex fork keep their own model settings.

Changes are read on the next dispatch. Worker runtime fingerprints include
the effective model and effort so reusable workers are recreated when those
settings change. A different model does not inherit the old model's context
window override.

Validation covers guided settings, configuration persistence and secret
redaction, provider A/B/A selection, defaults and all worker roles, and a
real bundled Broker process with an offline Codex App Server fixture that
verifies the child's effective model and reasoning effort.

Local validation: 1,198 ArgBridge tests passed, 11 environment-dependent tests
skipped; all 27 vendored Broker tests passed on a full rerun after one transient
workspace-reuse fixture failure. Type checking, production build and isolated
tarball installation passed.
