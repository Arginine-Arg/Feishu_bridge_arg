# arg-bridge v1.13.3

This release stabilizes the tmux client-disconnect regression test. Product
behavior is unchanged from 1.13.2.

## Fixed

- The disconnect fixture now waits for tmux to finish the client transition,
  then keeps its synthetic idle watchdog alive through both silent-paste
  recovery attempts. A heavily loaded runner can lose the initial paste after
  a client disconnect; the previous 1.5-second idle budget ended the fixture
  before recovery ran, and an 8-second budget still ended it before the second
  retry could render a response.

## Compatibility

- `/goal resume` continuation steering, third-party Responses provider
  steering, and all 1.13.2 behavior are unchanged.

## Validation

- 1,190 ArgBridge tests passed; 11 environment-dependent tests skipped.
- 27 vendored MixAgents Broker tests passed.
- The disconnect test passed after exercising both silent-paste recovery
  attempts with a 15-second observation window and a 2-second post-detach
  stabilization delay.
- Ubuntu CI keeps all assertions but runs Vitest with at most four workers to
  avoid contention between subprocess-heavy tmux fixtures.
