# arg-bridge v1.21.0

Fixes Bridge prematurely interrupting provider reconnects and exhausting a
three-attempt budget during long sessions. Recovery messages now contain only
`continue`.

Continuous recovery is enabled by default. Bridge nudges an explicitly retrying
active turn, normally at 15-second intervals, without sending `turn/interrupt`.
After a confirmed transient terminal state it checks the latest turn and goal,
then continues the same thread after 5 seconds. Codex retains its native
reconnect mechanism. A nudge cannot guarantee a provider reconnects sooner.

Control each main conversation from Feishu:

- `/recover off`: disable Bridge recovery, leaving current Codex work running.
- `/recover on`: enable recovery without reviving an old idle task.
- `/recover status`: show the setting, current turn and counters.
- `/stop`: stop the current task and cancel pending recovery.

The recovery override survives bot restarts and targets the main conversation
while a side is open. Legacy three-attempt default profiles migrate to
continuous recovery. Explicit finite budgets are available with
`continuous: false` and positive `maxAttempts`.

User stops, paused goals, approvals, provider restrictions, quota, authentication
and budget limits remain effective. Non-retryable failures and exhausted finite
budgets show the original Codex error. An uncertain turn-start result is not
blindly submitted again. Full structured text delivery from 1.19.0 is retained.

Update and restart each profile. Existing bindings require no new adoption.

Validation covers continuous and finite recovery, long sessions, state queries,
stop/off races, thread-specific persistent controls, settings migration and
real Codex fault injection. The release workflow runs all source and Broker
tests, type checks, builds and an isolated archive installation.

Observer teardown and bot restart also leave already accepted backend turns
running; only an explicit stop may interrupt a late accepted continuation.
