# arg-bridge v1.9.6

This patch fixes repeated `/btw` follow-ups and the remaining Broker runtime
recovery path, and aligns native slash-command behavior with Codex.

## Fixed

- `/btw` now follows up through the MixAgents Broker process that owns the
  existing side worker. Re-resolving an unchanged route no longer opens a
  second writer and fails with `already has an active writer`.
- Every `/btw` still re-reads cc-switch and validates the route revision.
  Provider, model or route changes continue to close the old side before a new
  worker is created.
- If a worker returns `agent_not_found`, Bridge keeps the newly resolved
  backend available for recreation instead of closing it before `spawn_agent`.
- Generated cc-switch runtimes now use the bundled compatible Broker directly
  when an older profile still names `mixagents-broker-mcp` or
  `mixagents-broker`. The generated route, provider, model and credential remain
  unchanged; the obsolete probe and repeated runtime-switch message are removed.
- Third-party Broker workers run Codex with `web_search = "disabled"`. Codex
  0.164 otherwise includes its native `web_search` tool for custom Responses
  providers. On halfapi this made an otherwise valid
  `deepseek-v4.1-flash` request return 503 or hang, while the same model and key
  succeeded with the ordinary function tools.
- `/model`, `/compact` and similar native slash commands are injected into the
  active live Codex terminal immediately. They no longer wait for the current
  task to finish, and they do not cancel that task. Adapters without safe direct
  injection retain next-turn queueing.

An upstream HTTP error is not treated as a route-selection failure. For example,
an HTTP 503 from the selected third-party endpoint remains visible and is not
replayed against the main session or another provider.

## Validation

- Two resolver instances with the same route reuse the original owner backend;
  the verification backend is closed and no second worker is spawned.
- An `agent_not_found` follow-up recreates the worker through the live
  replacement backend.
- Legacy wrapper selection starts the bundled Broker against the selected
  cc-switch runtime.
- A Codex request captured before and after the third-party wrapper confirms
  that `web_search` is removed without changing the selected model, function
  tools, provider, or credential.
- Active `/model` and `/compact` requests are injected directly without starting
  a second main run.
- Real `hallong_ds` acceptance returned `ROUND=1 ACK=ORBIT-731`,
  `ROUND=2 RECALL=ORBIT-731`, and `ROUND=3 RECALL=ORBIT-731`; consecutive
  `/btw` turns also completed on the same route.
- Typecheck, build and package installation passed; the full suite completed
  with 1149 passing tests and 12 explicit skips before publication.
