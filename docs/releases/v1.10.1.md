# arg-bridge v1.10.1

This release hardens `/btw` when the selected Broker provider is slow or the
profile still contains a legacy MixAgents launcher.

## Runtime recovery

- `arg-bridge-mixagents-mcp` is now recognized as a legacy generated-runtime
  wrapper. The bundled Broker is selected directly for cc-switch routes instead
  of starting the incompatible wrapper and then showing a fallback warning.
- Custom non-legacy MCP commands remain authoritative.

## Side visibility and timeout safety

- While waiting for the Broker terminal mailbox, Bridge emits a visible
  liveness update every 15 seconds.
- MixAgents 0.1.1 exposes terminal mailbox results rather than token deltas, so
  this is an honest wait heartbeat rather than fake streaming.
- Timeout means Bridge stopped waiting and requested an interrupt. It does not
  guarantee that remote provider work stopped immediately.
- The next `/btw` closes a timed-out or interrupted side and creates a clean
  agent. It no longer steers a fresh question into a possibly active old turn.
- Read-only status prompts explicitly prefer existing artifacts and receipts
  over launching new long calculations or broad filesystem scans.

## Validation

- Regression coverage includes the legacy `arg-bridge-mixagents-mcp` wrapper,
  heartbeat delivery, timeout diagnostics, and clean side rotation after a
  timeout.
- Existing `/btw`, provider switching, permissions, resume, Feishu/terminal,
  package installation, typecheck, and build gates remain in place.
- Local full suite: 1,171 tests passed and 12 environment-dependent tests
  skipped; the packaged 1.10.1 tarball also installed successfully.
