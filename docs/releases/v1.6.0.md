# arg-bridge v1.6.0

适配 Codex CLI 0.154.0+ 的 remote resume 权限协议，并加固 agent 进程守护与网络隔离。

## 修复

- `codex --remote ... resume <id>` 不再携带 `--dangerously-bypass-approvals-and-sandbox`、`--sandbox`、`--ask-for-approval`。0.154.0+ 会拒绝这种组合并在 bootstrap 阶段直接退出；远程任务必须继承创建时固化的权限。
- App Server 的 `thread/resume` RPC 仍优先应用 profile 权限策略；当服务端以确定性的 `Permission overrides are not supported when resuming a remote task` 拒绝时，只重试一次不带权限覆盖的请求，不会重试结果不明或其它失败。
- 旧的权限参数只保留给“新建本地 Codex 会话”，不再用于任何 `--remote` 附着路径（CLI native、structured view、legacy pane 接管）。
- Bridge 自己创建并固化 `dangerFullAccess` 的 thread 在后续 remote resume 后仍保持完整权限；由其它工具创建、权限更弱的 thread 无法被 TUI 强行提权，`arg-bridge native` 会打印冻结权限提示并按原权限附着，而不是崩溃。

## 网络隔离

- 新增 profile 级 `network.mode`：
  - `direct`：删除全部继承的代理变量，强制直连；
  - `proxy`：删除继承代理，只使用 `network.proxyUrl`，启动前做 TCP 可达性预检，不可达时直接失败而不是反复拉起；
  - `inherit`（默认）：保留宿主代理，但本机回环代理连接被拒绝/不可达时自动剥离，避免旧 clash / systemd 端口污染新进程。
- tmux 新建 session/window 时显式固定代理相关环境变量，避免 tmux server 中残留的旧端口覆盖 Bridge 已净化的子进程环境。

## 守护退避

- App Server 启动失败改为 3s / 6s / 12s / 24s … 上限 60s 的指数退避加抖动；连续失败后暂停新的拉起并输出清晰错误，避免短时间内重复建立会话触发供应商风控。
- systemd 用户单元使用 `RestartSec=3`、`RestartSteps` / `RestartMaxDelaySec`（systemd 254+）以及 `StartLimitIntervalSec=120` / `StartLimitBurst=5`；launchd plist 增加 `ThrottleInterval=10`。

## 验证

- 用真实 Codex CLI 0.155.0 复现 `Permission overrides are not supported when resuming a remote task`，修复后 native launcher 回归通过，并新增“TUI 必须先到达可用提示符、且不得出现该错误”的断言，避免旧的“只检查横幅”盲区。
- 真实 App Server `thread/resume` 拒绝路径的回退、代理净化、退避算法和 systemd/launchd 配置均有单元测试覆盖。
