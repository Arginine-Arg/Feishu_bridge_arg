# arg-bridge v1.10.0

This release gives `/btw` a Codex-like capability path without inheriting the
main session's write permissions implicitly.

## Explicit write task

Read-only remains the default:

```text
/btw Review the implementation
```

An individual side task may request workspace write only with an exact
workspace grant:

```text
/btw --write --workspace /canonical/project Implement the requested change
```

The command fails closed unless all of the following are true:

- `subagents.allowWriteWorkers=true`;
- the selected write/auto route permits `workspace-write`;
- the workspace is the current project or its child;
- the user supplied both `--write` and `--workspace` for this task.

The authorization applies only to that side task. The next `/btw` without the
flags closes the write-capable agent and recreates/read-only-routes the side.
Changing route, provider, model, access or workspace always forces a visible
worker replacement. The task body must be present in the same command; a later
message cannot inherit an earlier write grant.

## Codex-like side behavior

- Read-only side workers keep Codex's read/search/shell tools within the
  provider and sandbox capabilities.
- Explicit write tasks use a workspace-write Broker worker rather than
  escalating the main conversation and never use Codex fork fallback.
- The side task prompt is mode-aware: read-only workers are told not to modify
  files; authorized write workers receive the exact writable workspace.
- Provider/model choice remains independent from the main session and follows
  the selected side route.

## Validation

- Read-to-write and write-to-read transitions close the old agent.
- Missing workspace, disabled write workers, incompatible routes and broad
  paths fail closed.
- A reused writer is revalidated against the exact task and workspace before
  every follow-up, so an earlier write grant cannot authorize a later turn.
- Explicit write turns use `workerTimeoutMs` and normal provider reasoning;
  only read-only conversational sides use the fast 90-second policy.
- `/status`, settings and doctor report the effective side access and workspace.
- Existing `/btw`, timeout, provider-switch, Feishu/terminal and package gates
  remain covered by the full suite.
- Local release gate: `pnpm typecheck`, `pnpm build`, package installation, and
  the full Vitest suite with 1,169 tests passed and 12 environment-dependent
  tests skipped.

## Limits

This is not a blanket TUI privilege escalation. Main-scoped controls such as
`/model`, `/goal` and `/compact` remain on the main conversation. A write task
still depends on the selected Broker route, provider capability, and the
generated Broker `workspaceRoots` policy.
