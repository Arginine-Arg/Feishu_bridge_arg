# arg-bridge v1.11.0

This release vendors a small, source-auditable MixAgents Broker fork and gives
`/btw` true incremental progress instead of heartbeat-only waiting.

## Progress events

- Adds the backward-compatible `mixagents/events-v1` capability and
  `read_agent_events` MCP tool.
- Streams model text deltas, turn state and safe tool lifecycle metadata.
- Uses cursor pagination and long polling; no new transport is required.
- Keeps `wait_agent` terminal mailbox text and errors authoritative.
- Bounds each agent to 4,096 events and 1,000,000 event-text characters.
- Reports cursor loss explicitly when old events were discarded.
- Falls back to the existing 15-second liveness heartbeat with older Broker
  servers.

## Packaging and provenance

- Vendors MixAgents Broker 0.1.1 from upstream commit
  `09509e52bbd764fffd24c8591fb44476f770a2b9`.
- Rebuilds the vendored Broker from TypeScript during `pnpm build`; the
  installed `dist` is not hand-edited.
- Includes the upstream MIT license and a third-party notice in the release
  tarball.
- Removes the npm optional dependency on the same Broker package to avoid
  shipping two runtime candidates.
- The release package includes only compiled Broker files, not the source
  monorepo, tests or development tooling.
- Package preview: approximately 514 KiB compressed versus 480 KiB for
  1.10.1, an increase of about 7%.

## Safety

- Tool progress exposes only item type, item ID and lifecycle state.
- Command text, command output, file content, credentials and provider headers
  are not forwarded as progress events.
- Streamed and final model text are redacted before leaving ArgBridge.
- Existing read/write authorization, route fingerprinting, timeout rotation and
  fail-closed native collaboration rules remain unchanged.

## Validation

- Vendor Broker unit, MCP and release tests cover pagination, long polling,
  bounded buffers, cursor loss and tool metadata redaction.
- An ArgBridge process test launches the compiled vendored MCP server and a real
  fake Codex App Server, then verifies streamed text and terminal completion.
- ArgBridge unit tests cover text/tool progress forwarding, final-answer
  deduplication, secret redaction and legacy heartbeat-only Brokers.
- Full typecheck, build, package installation, cross-platform CI and release
  asset verification are required before publication.
- Local full gate: 1,174 ArgBridge tests plus 27 vendored Broker tests passed;
  11 environment-dependent tests skipped.
