# arg-bridge v1.6.3

修复 `/tmux bind` 拒绝 Codex 自带 daemon 暴露的 App Server socket 的问题（报错 `App Server socket 不安全`）。

## 问题

Codex v0.155 的 `codex app-server daemon` 会把控制 socket 放在 `codex-daemon-<uid>/` 下，并在运行目录里用**符号链接**指向它。arg-bridge 原先的校验明确拒绝符号链接，因此这类 pane 虽然能在 `/tmux list` 里被识别（thread 和 endpoint 都能读到），绑定却会失败：

```
tmux 操作失败：App Server socket 不安全
```

结果就是"列表里看得到、绑不上"。

## 修复

`/tmux bind` 现在会在**保持安全约束**的前提下解析这类 socket：

- endpoint 必须是绝对路径、不含 NUL；
- 路径的每一级父目录都不能被其它用户替换条目（属主不可写，或 `/tmp` 这类带 sticky 位的世界可写目录）；
- 解析符号链接后，最终目标必须是 **Unix socket** 且属主是当前用户；
- 解析结果按目录缓存，因此不会给每个请求增加重复的目录遍历开销。

仍然拒绝的情形：普通文件、目录、相对路径、位于 group/world 可写且无 sticky 位目录中的 socket、以及属主不是自己的 socket。

## 验证

- 在真实环境复现并确认修复：`/run/user/2103/mihomo-tmp/argbridge-rpc-…/server.sock` → 符号链接 → `/tmp/codex-daemon-2103/<hash>`（真实 socket，属主与权限 0600）。修复后解析成功，并通过 RPC 实际连上该 App Server（`initialize` + `thread/loaded/list` 返回了该 pane 承载的 thread）。
- 新增 `tests/unit/agent/app-server-socket-path.test.ts` 覆盖：普通 socket 通过、符号链接解析到 socket 通过、符号链接指向普通文件被拒、group 可写目录中的 socket 被拒、相对/空/不存在的路径被拒。
- 回归：`tests/unit/agent`、`tests/unit/platform` 与两个 App Server 进程测试全通过（34 文件 / 279 测试）。
