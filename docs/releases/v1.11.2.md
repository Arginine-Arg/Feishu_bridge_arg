# arg-bridge v1.11.2

This is a P1 in-place upgrade compatibility fix.

## Problem

ArgBridge 1.11 replaced the npm `mixagents-broker` optional dependency with a
vendored Broker. New processes resolved the vendor correctly, but a pre-1.11
process that remained running could keep an in-memory launch path pointing at:

```text
node_modules/mixagents-broker/dist/server.js
```

After the upgrade removed that path, the running process failed with
`MODULE_NOT_FOUND` before reaching any provider route. A new `doctor` process
could simultaneously report the vendor as healthy, creating a split-brain
diagnostic state.

## Fix

- Restore `mixagents-broker@0.1.1` as an optional compatibility dependency.
  It exists only so pre-1.11 processes can resolve their old module path.
- New processes continue to prefer the vendored Broker with `events-v1`.
- If a current process reads a stale profile path containing
  `node_modules/mixagents-broker/dist/server.js` and that file is absent,
  ArgBridge substitutes the vendored entry with a visible notice.
- Doctor reports both `vendorBroker` and `legacyNpmBroker` presence.
- Node 20 is handled explicitly: npm omits the legacy package because its
  declared engine is Node >=22.19, while the vendored Broker remains available.
- The optional package does not change provider, model, route, credentials or
  worker pinning.

## Upgrade behavior

- Installing 1.11.2 restores the legacy filesystem path, so an already-running
  pre-1.11 process can continue using Broker without terminating its research.
- New threads/processes use vendor and gain current `events-v1` behavior.
- An old running process cannot acquire new in-memory code without restart;
  1.11.2 only preserves its compatibility.
- A manual symlink used as emergency mitigation may be removed after the
  package-manager install has restored the legacy optional dependency.

## Validation

- Tests cover the legacy npm entry, vendor entry, stale profile-path substitution
  and doctor reporting.
- Package installation verifies both resolvers in the installed global layout.
- Existing `/btw`, worker streaming, timeout continuation and provider pinning
  regression suites remain required before release.
- Local full gate: 1,178 ArgBridge tests plus 27 vendored Broker tests passed;
  11 environment-dependent tests skipped.
