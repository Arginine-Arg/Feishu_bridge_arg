# arg-bridge v1.9.9

This patch fixes two `/btw` diagnostics that made a bounded timeout and Broker
startup recovery look mysterious.

## Fixed

- Agent-side timeouts no longer reuse the conversational idle-watchdog card.
  A 90-second `/btw` timeout now displays its actual actionable error instead
  of `0 分钟无响应`.
- Idle-watchdog timeout rendering remains unchanged for genuinely stalled main
  conversations.
- Generated cc-switch runtimes recognize legacy Broker launchers named
  `mixagents-broker`, `mixagents-broker-mcp` and their `.js`, `.mjs`, `.cjs`,
  `.cmd` or `.exe` forms, including `node /path/mixagents-broker-mcp.mjs`.
- These known legacy wrappers are bypassed immediately in favor of the bundled
  Broker. Custom MCP commands for manual routes remain authoritative.

## Behavior

If the first `/btw` is a large multi-file investigation and exceeds
`sideTimeoutMs`, the side is stopped and the card explains the real budget.
A later short prompt such as `hi` can still succeed when the provider and
Broker have recovered. Increase `/btw` timeout in advanced settings when the
side task genuinely needs longer, or keep exhaustive work on the main session.

## Validation

- Typecheck, build, package installation, targeted lifecycle tests and the full
  suite pass (`1158 passed`, `12 explicit skips`).
- A long timeout is rendered as an error containing `90 秒超时`; `0 分钟无响应`
  is absent.
- Plain, `.mjs` and node-launched legacy Broker wrappers select the bundled
  Broker for generated cc-switch runtimes.
