# arg-bridge v1.17.0

Adds in-place provider switching for Bridge-managed native threads:

```bash
arg-bridge native --bridge <thread-id> --follow-current-provider --profile codex
```

Unlike `--adopt --follow-current-provider`, this command keeps the exact same
Codex thread ID and full native resume state. It resolves the current cc-switch
provider, model and credential generation and reopens the thread without copying
or truncating its history.

Codex records the provider used when a thread starts and normally rejects a
different current provider during `thread/resume`. Bridge now starts a scoped
provider-generation App Server with a compatibility alias. The historical
provider ID remains available to Codex for thread validation, while its endpoint,
credential, wire API and headers point to the current cc-switch provider. The
model is updated to the current provider's configured selection.

The command is fail closed at ownership boundaries:

- an active turn is rejected;
- an old-provider App Server that still owns the thread is rejected rather than
  creating a competing writer;
- the thread must already have a valid Bridge marker;
- provider, model or credential resolution failures stop before resume.

If an old TUI still owns the thread, exit that TUI and run
`arg-bridge restart --profile <profile>` to reclaim the idle App Server. The
same command can then reopen the original thread ID.

The Bridge marker records `compatibilityProvider`, the current provider
generation and the unchanged thread creation time. Repeating the command
reconstructs the same compatibility host idempotently, including after the host
has been reclaimed.

Validation includes real Codex App Server/provider switches that remove the old
provider from `config.toml`, same-ID resume, current-model requests,
and compatibility-host reconstruction on a repeated command. Active turns and
old writers remain fail closed.

Local validation: 1,226 ArgBridge tests passed, 12 environment-dependent tests
skipped, and all 27 vendored Broker tests passed. Type checking, production
build, isolated tarball installation and CLI version verification passed.
