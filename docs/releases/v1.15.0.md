# arg-bridge v1.15.0

This release fixes stale file-delivery capabilities across main sessions,
`/btw` workers, model-visible subagents and live tmux terminals.

## Fixed

- Artifact capabilities are persistent per chat scope. A turn ending no longer
  revokes the token still held by a structured main session or reusable side
  worker.
- Active main and side workspace roots are merged into the same scope grant.
  Artifact paths can resolve beneath any currently authorized root.
- MixAgents side and subagent controller environments receive the current
  `LARK_CHANNEL_*`, artifact socket/token and file-delivery generation.
- A reusable worker is recreated when its artifact capability generation
  changes, rather than receiving a follow-up with an environment that can no
  longer send files.

## Stale token recovery

Long-lived processes may still contain a token from before this update. The
CLI:

1. prefers the current token stored in the managed tmux session;
2. if the broker reports an expired token, reads the profile-local mode-0600
   grant state;
3. selects only the newest persistent grant for the same artifact socket whose
   allowed roots contain the current cwd;
4. retries once through the existing broker socket.

Recovery does not bypass the sandbox. The broker still requires a
cwd-relative regular file, rejects `..` and symlinks, verifies realpath
containment and the profile's local-file root policy, enforces the file-size
limit, and binds delivery to the grant's chat and reply target.

## Validation

- 1,194 ArgBridge tests passed; 11 environment-dependent tests skipped.
- 27 vendored MixAgents Broker tests passed.
- Artifact broker coverage verifies stable tokens and multiple authorized
  workspace roots.
- CLI coverage verifies stale-token recovery selects only the newest matching
  cwd root.
- `/btw` and Broker tool coverage verifies workers are recreated when the
  artifact generation changes.
