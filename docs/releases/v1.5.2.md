# arg-bridge v1.5.2

修复 legacy Codex pane 自动迁移失败的问题。

- Bridge 在 `/tmux bind` 时先调用 `thread/resume` 加载旧 rollout，再创建 remote pane；thread 不存在或 writer 冲突时不会创建新 pane。
- 从 pane 进程树读取 `CODEX_HOME`，避免 Bridge daemon 与旧 Codex 使用不同会话目录。
- remote pane 启动/校验失败时，只清理本次新建的 pane，不触碰用户原 pane。
- 保留 v1.5.1 对 `-m`、`--model` 等 CLI 参数误判为 thread ID 的修复。

使用方式：

```text
/tmux list
/tmux bind <legacy pane 编号>
/tmux status
```

不需要手动启动 App Server 或复制 endpoint。默认 workspace 不会被修改。
