# arg-bridge v1.12.0

This release makes active-task message delivery explicit and auditable.

## Behavior change

Ordinary messages sent while a task is running now queue for the next turn.
They no longer opportunistically steer into the active turn.

Use:

```text
/steer <text>
```

to add input to the current main turn. `/steer` does not start a second run,
stop the goal, reset the thread, or change its provider/model.

## Transport support

- Official structured Codex calls `turn/steer` with the exact active turn ID.
- Live Codex writes to an empty native composer and uses Tab-to-queue.
- Multiple explicit steering calls are serialized per chat scope.
- The ordinary message queue keeps FIFO order; `/steer` is a separate control
  path and does not reorder queued work.

## Fail-closed cases

`/steer` returns an explicit error and does not silently enter the ordinary
queue when:

- no main turn is active;
- a `/btw` side conversation may own the terminal;
- the message has attachments or a quoted reply;
- the body is empty;
- the provider does not support safe turn steering;
- the live composer/turn is no longer in a safely steerable state;
- the backend reports an uncertain delivery outcome.

An uncertain result is never replayed automatically.

## Diagnostics and help

- `/status` now reports steering availability separately from queue state and
  distinguishes provider, side-conversation, stopping and terminal restrictions.
- `/help` is grouped into active-task messaging, sessions/workspaces, side
  conversations, diagnostics and local collaboration sections.
- Busy acknowledgements explain the difference between ordinary queueing,
  `/steer`, `/status` and `/stop`.

## Upgrade behavior

This release includes all `1.11.2` fixes for in-place Broker upgrades, stale
legacy Broker paths and silently dropped tmux paste delivery.

Install normally, restart the Bridge profile, then use `/help` and `/status` to
verify the new behavior. Existing thread history and provider/model bindings
remain unchanged. The running Bridge process must be restarted to load the new
runtime code.
