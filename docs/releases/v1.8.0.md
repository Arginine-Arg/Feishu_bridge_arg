# arg-bridge v1.8.0

v1.8.0 upgrades MixAgents from `/btw` and RSI-only consumers into
Bridge-owned, model-visible orchestration for Bridge-managed Codex sessions.

## Highlights

- Codex 0.164 App Server dynamic tools expose `arg_bridge.spawn_agent`,
  `followup_task`, `wait_agent`, `list_agents`, `list_routes`,
  `interrupt_agent`, `close_agent` and an explicit queue-only `send_message`
  contract.
- New Bridge threads enable the MultiAgentV2 host-tool path and disable native
  tools. Parent task text reaches Broker workers as ordinary plaintext input,
  not `agent_message.encrypted_content`.
- Multiple workers, route/provider/model fingerprints, persistent logical-path
  mappings, restart recovery, cancellation, timeout, idempotency and result
  mailboxes are supported.
- The public `mixagents-broker@0.1.1` npm package is an optional dependency and
  its stable MCP entry is discovered automatically when available.
- Read and write routes are wired independently. Write workers are disabled by
  default and require the user-issued
  `arg-bridge-write --workspace /canonical/path --task <task>` directive; model
  tool arguments cannot self-grant write access.
- Project RSI findings can return to the parent for bounded repair rounds, after
  which the upstream runner/validator and reviewer must pass again.
- Settings and doctor report dynamic-tool wiring, native-shadow/bypass state,
  worker-probe status, read/write routes, RSI loop status and direct-TUI hook
  limitations without printing credentials.
- Settings now presents a guided cc-switch account and route selection flow in
  plain language, writes only provider-ID/route-ID mappings, and reserves
  low-level controls for an explicit advanced prompt.

## Compatibility

Codex 0.164.0 is the verified App Server baseline. New Bridge-managed threads
carry a persisted Broker-tool marker. Old 1.7.x threads do not have that marker
and fail closed on resume instead of falling back to native encrypted child
messages. Start a new Bridge-managed conversation after upgrading.

Direct `codex` TUI sessions remain outside this dynamic-tool path. Codex hooks
can block or rewrite native calls but cannot replace a call with a Broker result;
direct-TUI Broker routing therefore requires a future trusted plugin/hook.

`/btw` remains read-only. Broker-required mode does not silently fork. `auto`
mode may use the documented `/btw` fork fallback, but model-visible Broker tools
never pretend a native Codex child is a MixAgents worker.

## Rollback

Stop the profile, reinstall v1.7.2, and start a new thread. The v1.8.0 state files
(`broker-threads.json`, `broker-workers-*.json`) are ignored by v1.7.2; keep
them if you plan to return to v1.8.0. No provider secret is stored in these
files.
