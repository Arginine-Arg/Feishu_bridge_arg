# arg-bridge v1.13.1

This patch fixes explicit `/steer` for structured Codex sessions, including
sessions running through a third-party Responses provider selected by
cc-switch.

## Fixed

- The preferred structured transport now forwards `steerCapability` and
  `steer` from the selected backend. Previously it exposed only `stop` and
  `detach`, so `/steer` reported a generic provider error even when the active
  Codex session supported steering.
- Third-party provider identity no longer blocks `turn/steer`. The active
  Codex App Server turn is authoritative: accepted input is injected into that
  turn, while an explicit protocol rejection remains unavailable and is never
  silently replayed or moved into the ordinary queue.

## Usage

```text
/steer <new direction for the current main turn>
```

Use `/status` to inspect the current capability. `/steer` remains unavailable
when there is no active main turn, a side conversation is active, the run is
stopping, or the terminal composer cannot safely accept input.
