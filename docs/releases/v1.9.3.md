# arg-bridge v1.9.3

This patch repairs Bridge-managed native resume and adoption after updating
from an older session.

## Fixed

- Canonicalizes App Server endpoints before writer-ownership checks. A socket
  exposed through a Codex daemon symlink and a saved tmux binding no longer
  appear as two competing owners when they resolve to the same socket.
- Moves App Server sockets from disposable `TMPDIR` directories such as
  `/run/user/<uid>/mihomo-tmp` to stable XDG runtime/state directories, with a
  short-path fallback when the Unix socket path would exceed the platform
  limit.
- Adds durable reconnect guidance:
  `arg-bridge native --bridge <thread-id> --profile <name>`. Raw
  `codex --remote unix://...` remains a live-socket command and is not treated
  as durable after the App Server exits.
- Makes `--adopt` idempotent. A repeated migration of the same source thread
  resumes the newest existing marker instead of creating another thread.
- Reloads `broker-threads.json` on a marker miss, so a Bridge daemon that was
  already running when `--adopt` completed can bind the new thread immediately.
- Preserves the old-thread limitation: Codex 0.164 `thread/resume` cannot add
  dynamic tools in place. Existing unmarked threads still require `--adopt`
  and continue under a new Bridge-managed thread ID.

## Validation

- Symlinked endpoint aliases canonicalize to one endpoint.
- Stable runtime paths avoid `mihomo-tmp` and respect Unix socket length limits.
- Repeated adoption reuses the same destination thread and preserves its
  marker timestamp.
- A marker written after daemon startup is visible to `/tmux bind` without a
  restart.
- Real Codex App Server E2E covers new, attach, cold-resume and adopted
  Bridge-native threads.
- Full unit, integration, process, package, typecheck and build gates run
  before publication.
