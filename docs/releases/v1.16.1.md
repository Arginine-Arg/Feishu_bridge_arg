# arg-bridge v1.16.1

Fixes missing file-delivery capabilities in existing native/adopted main
sessions, `/btw` sessions and Broker subagents. This is a different failure
from the expired tokens addressed in v1.15.0: some App Servers were started
without the capability environment at all, and restarting the bot could not
change those already-running processes.

Update and restart each bot profile:

```bash
curl -fsSL https://github.com/Arginine-Arg/Feishu_bridge_arg/releases/latest/download/install-global.sh | sh
hash -r
arg-bridge --version
arg-bridge restart --profile codex
```

For sessions already bound to that profile, no new `native`, `--adopt`,
Ctrl-C or `/btw out` operation is required. The bot restores private file
capabilities from its saved thread/chat bindings when it starts. The updated
`arg-bridge sendfile` command uses the calling Codex thread ID to find that
exact binding, even when the old App Server has no capability environment.
Workers created later by a still-running pre-upgrade native controller can
recover through that controller's persisted native worker IDs as well.

The preferred adapter now forwards capability restoration. Worker refreshes
and live terminal handoffs include the chat scope; a shell that filters the
token can recover it only with a matching scope and broker socket. Relative
file paths are resolved from the caller's actual cwd inside approved roots.
Windows named-pipe grants carry an explicit state-file path, and pipe
addresses remain stable when a broker is recreated.

If a Codex read-only or workspace-write sandbox prohibits the broker socket,
the command submits a signed request through its normal tool output. The bot
reads only actual tool-result entries for authorized threads and performs the
upload with the same file policy. This keeps the existing sandbox intact.
The command reports a pending request; delivery is confirmed by the Feishu
attachment or an explicit failure reply. No raw token appears in tool output,
and persistent nonce receipts prevent replay across bot restarts.

Capability index directories are private (0700) and files are 0600, owned by
the current user. Unknown threads, conflicting chat bindings, unsafe index
files, paths outside approved workspaces, symlinks and oversized files remain
rejected. The recipient is never inferred just from a shared workspace.
Sessions that were never bound to a Bridge chat still require a valid chat
binding before they can deliver files.

Validation includes a broker restart with pre-upgrade main/side/worker state,
a worker created after restart by an old native controller, token filtering
and renewal, recipient isolation, cwd containment, private-file checks, and
a separate Node process with no inherited delivery environment.
