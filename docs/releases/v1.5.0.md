# arg-bridge v1.5.0

本版简化旧 terminal 会话迁移到 structured Codex 的流程。

- `/tmux list` 识别普通 `codex resume <thread-id>` legacy pane，并显示为可迁移 pane。
- `/tmux bind <编号>` 会由 Bridge 自动启动私有 App Server、创建带 `--remote` 的新 pane、校验 thread 和 socket，然后保存绑定。
- 不再要求用户手动填写 endpoint、创建 App Server socket 或复制内部连接命令。
- 原 legacy pane 会保留，直到新 structured pane 验证成功；成功后用户可以手动关闭旧 pane。
- 结构化 pane 继续支持关闭、重新打开和 resume；下一条飞书消息按当前 pane 的 endpoint/thread 提交。
- App Server 只提供结构化控制通道，不会额外启动第二个模型任务或增加 Bridge 系统提示词。

使用方式：

1. 将 profile 设置为 `agentTransport: "structured"` 和 `structuredNativeView: true`。
2. 在 tmux 中打开 pane，运行普通 `codex resume <thread-id>`；也可以保留原来的 Codex pane。
3. 在飞书发送 `/tmux list`，然后发送 `/tmux bind <编号>`。
4. 发送 `/tmux status` 和 `/status` 验证，再发送普通消息。

限制仍然存在：Claude 任意外部 pane 没有官方本地 attach 协议；不同 workspace 或不属于当前用户的 App Server socket 会被拒绝；`/tmux unbind` 会关闭该 scope 的自动重新发现。
