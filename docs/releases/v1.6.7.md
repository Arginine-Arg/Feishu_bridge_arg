# arg-bridge v1.6.7

修复 `cc-switch` 切换 provider 后旧 Codex thread 无法 resume 的问题，同时保持 `/model` 的线程级选择不被覆盖。

## 问题

Codex 会把创建 thread 时的 `model_provider` 固化在 thread 元数据中。`thread/resume` 会先解析这个历史 provider id，再应用当前 `config.toml`。如果 `cc-switch` 已把旧 id（例如 `deepseek`）替换为新的稳定 id（例如 `custom`），旧会话会在加载阶段失败：

```
failed to load configuration: Model provider `deepseek` not found
```

修改环境变量、API key、代理或重启进程都无法修复，因为失败发生在 thread 加载阶段。

## 修复

- App Server `initialize` 响应里的 `codexHome` 被保存到 RPC 客户端；连接时还会用 App Server 的 spawn 环境/已知 profile home 做种子，服务端返回值优先。
- `thread/resume` **先按原样执行**，不注入 provider/model。这样正常的会话（包括用户通过 `/model` 选择的模型）完全不受影响。
- **仅当**服务端明确返回 `Model provider <id> not found` 时，才从该 `codexHome` 的 `config.toml` 读取当前 `model_provider`/`model` 并重试一次；调用方显式传入的参数优先级更高。
- 权限覆盖被拒绝（remote resume）与 provider 缺失可以组合重试，顺序为：正常 → 去权限覆盖 → provider 重绑；最多 3 次，且每次只针对确定性的拒绝，不重试超时或结果未知的请求。
- 配置缺失/不可读、或无法确定 App Server home 时**不猜测**：记录 `codex-resume-defaults-unavailable` / `codex-provider-rebind-unavailable` 并抛出原始错误，不会静默把第三方 thread 绑到 `openai`。
- 不重写历史消息、不迁移 thread、不修改 rollout/数据库；只改变 resume 请求参数。

## 验证

- 真实 Codex 0.155.1 + 真实 rollout（`model_provider: deepseek`，当前 config 改为 `custom`）：
  - 原始 resume：``failed to load configuration: Model provider `deepseek` not found``；
  - 修复后：同一 thread id 成功 resume；
  - 通过 `/model` 选择 `model-user` 后再次 resume：仍为 `model-user`（不再被 config 的 `model-new` 覆盖）。
- 新增 `tests/unit/agent/codex-provider.test.ts`：配置读取、profile 优先、无 home/无配置不猜测、可读但无 provider 时才使用 openai。
- 新增 `tests/unit/agent/rpc-codex-home.test.ts`：initialize 捕获、种子回退、旧服务端不返回时的行为。
- 重写 `tests/unit/agent/structured-permissions.test.ts`：正常 resume 不注入、provider 缺失才重绑、显式参数优先、权限/provider 组合重试、无 home/config 不重试。
- 新增 `tests/process/codex-provider-resume.test.ts`：模拟 App Server 的 provider 缺失、正常、权限重试、组合重试四条完整 RPC 路径。
