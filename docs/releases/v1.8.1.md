# arg-bridge v1.8.1

This release makes the normal MixAgents worker flow zero-configuration for
cc-switch users.

Highlights:

- The current cc-switch Codex provider is resolved from SQLite (with legacy
  JSON fallback), including its model, endpoint, wire API and credential.
- `follow-cc-switch` generates a profile-private Broker route and provides the
  credential only to the MixAgents child environment. No manual route map or
  credential JSON is required.
- Provider changes are reflected on the next worker operation. Old workers are
  recreated when the provider/config fingerprint changes.
- Third-party providers fail closed for native fork/collaboration; native
  fallback is restricted to eligible official providers and explicit settings.
- `send_message` queues plaintext locally and is delivered by the next
  `followup_task`, enabling three-round stateful worker conversations.
- `arg-bridge settings` now asks only whether workers follow the current
  cc-switch provider or use a fixed provider.
- Doctor no longer reports Broker tools as wired without a matching
  `broker-threads.json` marker and a live identified profile App Server.
- Added a real three-round cc-switch/MixAgents acceptance test and explicit
  native dynamic-tool/namespace traces.

Validation includes typecheck, unit, integration and process suites, package
installation, Codex dynamic-tool tracing, real MixAgents MCP, and a real
three-round worker run using the current cc-switch provider. Secrets are
reported only by field path, presence, and one-way fingerprint.
