# arg-bridge v1.6.2

让 `cc-switch` 一类的 provider 切换开箱即用：第三方 Codex provider 自动拿到凭据、不再继承本机代理，`arg-bridge restart` 回收仍持有旧 provider 的 Codex App Server。

## 第三方 provider 网络策略

- `inherit` 模式下，当前 Codex provider 是第三方（`base_url` 不在 `api.openai.com` / `chatgpt.com`，或使用自定义 provider id）时，**继承的本机回环代理会被剥离**，即使该端口仍然存活。本机 clash / 中继端口无法访问国内或内网端点，它的死端口变体是 `Missing environment variable` 之外的另一半故障。
- 规则刻意收窄，避免影响正常用法：
  - provider 是第三方且代理指向远端主机时**保留**代理，因为那可能是访问该端点的唯一通路；
  - provider 为官方（`openai` id 或官方 `base_url`）时完全不变，`clash on` 流程照常；
  - `network.mode` 显式为 `proxy` 时以 `proxyUrl` 为准，第三方规则不生效。
- 判定在每次运行时从 `config.toml` 读取，并提供 `thirdPartyProvider` 选项给 `sanitizeAgentEnv`；剥离动作记录 `network.proxy-stripped`，`reason=third-party-provider`。
- `arg-bridge native` 走同一条策略，因此 CLI 侧也不会再把第三方流量送进旧代理端口。

## App Server 生命周期

- Codex App Server 是 detached 进程，启动时的 provider、凭据、代理和模型目录都固化在进程里。此前 bridge 重启或 `cc-switch` 切换后，旧 server 仍会继续服务，导致前台出现旧环境。
- 新增 `<profile>/structured/app-server-registry.json`，按 profile 记录运行目录、进程号、二进制与环境指纹（凭据摘要、生效网络模式、`config.toml` / `auth.json` 文件时间戳）。**只保存凭据的 sha256 摘要，不保存 token 明文**，文件权限 `0600`。
- 连接时的行为：
  - 指纹与 owner 未变 → 复用正在运行的 server，不做重启；
  - 指纹变化（provider 切换、token 轮换、网络策略变化）→ 终止旧 server 并在同一目录重新拉起；
  - 记录的进程已退出 → 清理后重新拉起。
- `arg-bridge restart --profile <name>` 在重启前回收该 profile 记录的 App Server，并打印回收数量；`arg-bridge start` 启动时同样回收上一轮遗留的 server。
- `arg-bridge native` 退出时注销自己这个 owner；若没有其它 owner（其它 bridge 或暂停的 native TUI），会停掉它启动的 server，避免孤儿进程持有旧环境。
- 仍被其它 owner 持有的 server 会保留，保证暂停的 native TUI 可以继续重连。

## 验证

- 新增 `tests/process/cc-switch-acceptance.test.ts`，用假 codex 二进制同时覆盖 turn 路径与 structured 路径：在 `OPENAI_API_KEY` 为空、`HTTPS_PROXY` 指向死端口、`config.toml` 使用第三方 provider 的条件下，子进程实际拿到 `experimental_bearer_token` 且没有任何代理变量；App Server 注册表内容只包含摘要，不含 token。
- 新增 `tests/process/codex-app-server-lifecycle.test.ts`：指纹未变时复用同一 server 进程；改写 `config.toml` 与 token 后旧进程被终止并重新拉起；最后一个 owner 退出时 server 被回收；仍有其它 owner 时保留。
- 新增 `tests/unit/agent/host-registry.test.ts` 覆盖指纹比较、owner 剪枝、陈旧判定（环境变化 / owner 退出 / 进程消失 / 未记录目录）与凭据摘要不落明文。
- `network-env` 单测扩展到第三方回环剥离、远端代理保留、显式 `proxy` 模式优先。
- 全量 `pnpm test`：129 个文件 / 1004 passed、0 failed；`pnpm typecheck` 通过。
