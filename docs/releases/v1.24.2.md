# v1.24.2

## Reclaim idle servers even with a TUI attached

1.24.1 stopped the bot before reclaiming App Servers, but a native TUI still
held the shared server open. The restart skipped it, and the next `--adopt`
reconnected to the same stale catalog.

The restart now probes each in-use server:

- `thread/loaded/list` plus the profile's bound thread ids;
- `thread/read` with `includeTurns: false` for each thread.

If every thread is idle, the server is reclaimed. If any thread is active, it
is skipped and reported. A failed probe is treated as busy.

The TUI shows a lost connection when its idle server is reclaimed; re-run
`arg-bridge native --bridge <thread-id>` to attach again. Thread history and
permissions are unchanged.

## Verification

- Unit tests cover idle, active, unreadable and empty-loaded-list probes.
- Restart order test still asserts `stop -> terminate -> start`.
- Existing host-in-use test remains green.
