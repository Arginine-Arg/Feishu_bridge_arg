# arg-bridge v1.13.0

This release adds safe provider-generation migration for existing Codex
threads.

## Usage

```bash
arg-bridge native --adopt <old-thread-id> --follow-current-provider
```

Plain `--adopt` continues to preserve the source thread's provider/model.
`--follow-current-provider` preserves only bounded user and assistant text,
then creates the Bridge-managed destination under the provider, model and
credential fingerprint currently selected by cc-switch.

## Safety model

- The old thread remains read-only and is inspected only through its
  authoritative owner at an idle boundary.
- The destination uses a separate App Server keyed by the current
  provider/model/credential/config fingerprint. It never reuses the old
  provider's App Server.
- `thread/start` receives explicit `modelProvider` and `model` values.
- The returned provider/model and thread identity are verified before the TUI
  starts.
- Missing cc-switch provider ID, Codex `model_provider`, model or credential
  fails before creating a destination thread.
- The source thread's goal/tool history, encrypted payloads, images and tool
  outputs are not copied.

## Idempotency

`broker-threads.json` records:

- source thread ID;
- cc-switch provider ID;
- Codex model provider and model;
- an opaque runtime fingerprint covering provider, model, credential and
  config/auth generations.

Repeating the same follow-provider migration reuses the destination for that
exact provider generation. Switching providers creates a distinct destination
without overwriting an earlier migration.

## Validation

- 1,187 ArgBridge tests passed; 11 environment-dependent tests skipped.
- 27 vendored MixAgents Broker tests passed.
- Unit tests cover provider-generation marker selection, missing provider/model
  and missing credential fail-closed behavior.
- Real Codex 0.164 App Server E2E passed: a legacy thread was migrated after
  config switched to a different model provider/model; the destination host
  registry and provider request both showed the new model, bounded legacy text
  remained present, and repeated migration reused the same destination.
