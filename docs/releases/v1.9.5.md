# arg-bridge v1.9.5

This patch fixes interactions between a running main Codex task and new Feishu
input.

## Fixed

- `/btw` now remains an independent side run while the main task is active. A
  missing routed `inputMode` can no longer turn it into a competing main run or
  produce `run-already-active`.
- Broker side turns use `subagents.workerTimeoutMs`. The generic conversation
  idle watchdog no longer terminates a healthy side worker that is waiting
  silently for a provider response.
- Messages sent during a live task continue to use native Tab/`turn/steer`
  semantics where supported, or queue for the next turn when steering is not
  available.
- Native slash commands no longer cancel a running live task merely to execute
  immediately. They queue for the next idle boundary.
- Third-party structured Responses providers no longer use provider-dependent
  `turn/steer`; ordinary input queues for the next turn. Official providers
  retain native steering.
- The selected-provider credential precedence introduced in 1.9.4 remains in
  force for `/btw`, model-visible workers, native Bridge workers and RSI
  reviewers.

## Validation

- Main run plus `/btw` side run completes concurrently with one main scope and
  one side handle.
- Side worker `wait`/`send` receive `subagents.workerTimeoutMs`.
- Side operations are exempt from the conversational idle watchdog.
- Normal messages are steered when available and queued when unavailable;
  neither stops the active task.
- Native slash commands and third-party structured input queue for the next
  turn without cancelling current work.
- Full unit, integration, process, typecheck, build and package gates run
  before publication.
