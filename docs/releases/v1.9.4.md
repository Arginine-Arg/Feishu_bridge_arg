# arg-bridge v1.9.4

This patch fixes subagent credential precedence when the main session and the
selected subagent provider use different API keys.

## Root cause

MixAgents 0.1.1 gives an inherited environment variable priority over
`MIXAGENTS_BROKER_CREDENTIALS_JSON`. If the Bridge process inherited the main
session's `OPENAI_API_KEY`, the Broker worker could therefore send that key to a
different selected provider and receive an upstream `401 Invalid token`.

## Fixed

- Bridge now explicitly applies every credential resolved from the selected
  cc-switch provider to the MixAgents MCP child environment.
- Existing environment entries with the same name, including case variants,
  are replaced before the child starts.
- `/btw`, model-visible `arg_bridge.*` tools, native Bridge workers and RSI
  reviewers all share the corrected backend path.
- Credential values remain limited to the child process environment and are
  not added to routes, mappings, logs, diagnostics or prompts.

## Validation

- Regression test uses a deliberately wrong inherited `OPENAI_API_KEY` and
  verifies the `/btw` Broker process receives the selected provider key.
- A second regression verifies the same behavior through
  `BrokerToolController` model-visible subagent tools.
- Real `halflong_ds` three-round acceptance keeps the normal main key in the
  parent environment and still returns:
  `ROUND=1 ACK=ORBIT-731`,
  `ROUND=2 RECALL=ORBIT-731`,
  `ROUND=3 RECALL=ORBIT-731`.
- Unit, integration, process, typecheck, build and package gates run before
  publication.
