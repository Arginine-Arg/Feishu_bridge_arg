# v1.24.1

## Restart actually recycles the catalog

Codex reads `model_catalog_json` once when an App Server starts. A long-lived
shared server therefore keeps an old model list even after Magpie rewrites the
catalog.

`arg-bridge restart` used to reclaim App Servers while the bot was still
connected. The bot's own socket counted as an active client, so every shared
server was reported "in use" and skipped. The restart then reconnected the bot
to the same stale server.

The restart now:

1. stops the bot;
2. waits for its socket to close;
3. reclaims idle App Servers;
4. starts the bot again.

A server still attached to a native TUI is still skipped and reported, so a
running terminal is not interrupted.

## Verification

- Unit test asserts the order `stop -> terminate -> start`.
- Existing host-in-use and host-registry tests remain green.
