# arg-bridge v1.9.2

This patch fixes `/btw` when cc-switch resolves a provider but MixAgents does
not return the runtime route generated from that provider. Its primary goal is
to keep the settings-selected provider, not merely add a fallback.

## Fixed

- The subagent-selected cc-switch provider remains the first and preferred
  route.
- A missing or mismatched generated route causes a bounded MCP runtime restart.
- If an older or stale external MCP entrypoint still ignores the generated
  configuration, Bridge retries with the bundled
  `mixagents-broker@0.1.1` runtime and continues with the same selected
  provider, model, endpoint and credential.
- The recovery is visible in the `/btw` stream and Broker `list_routes`
  response.
- Only after the primary provider cannot be recovered does eligible
  `mode=auto` use a read-only Codex `thread/fork` on the main session's
  provider/model when `allowForkFallback=true`.
- The fallback delivers the task as ordinary user input. It does not use native
  collaboration `agent_message` or `encrypted_content`, so third-party
  Responses providers remain supported.
- Manual routes, explicit `/btw --route <id>` and `mode=broker` still fail
  closed. They never change provider silently.
- The visible bridge notice reports why the MixAgents provider was skipped and
  that the main Codex provider is being used.

## Validation

- A one-shot missing route is recovered by restarting the MCP process and keeps
  the selected cc-switch provider.
- A persistently stale external MCP server is replaced by the bundled
  compatible runtime and keeps the selected cc-switch provider.
- The real cc-switch provider completed the three-round worker acceptance:
  `ROUND=1 ACK=ORBIT-731`, `ROUND=2 RECALL=ORBIT-731`, and
  `ROUND=3 RECALL=ORBIT-731`.
- `mode=broker` never silently changes to the main provider.
- Explicit `--route` and manual route mode still fail closed.
- Missing credentials/startup tools fall back only in eligible auto mode.
- Structured adapter regression verifies that `main.forkSide` receives the
  original `/btw` task body with a forced `read-only` sandbox.
- Full unit, integration, process, typecheck, build and package gates are run
  before publication.
