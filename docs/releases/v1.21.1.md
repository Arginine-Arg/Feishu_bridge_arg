# arg-bridge v1.21.1

Fixes `arg-bridge native --adopt <thread-id> --follow-current-provider` on very
large Codex sessions. Version 1.21.0 attempted full thread hydration before its
recent-tail fallback. On a 210 MiB session, the single JSON-RPC response exceeded
the 32 MiB websocket `maxPayload`, closed the channel, and the fallback reused
that dead channel. The resulting error incorrectly said the recent tail was
empty.

Adoption now:

- reads only thread status before paging;
- uses small `thread/turns/list` pages with the protocol's default summary
  item view;
- streams the canonical local rollout JSONL when pagination is unavailable or
  its response would be too large;
- keeps only the newest 48,000 characters of user/assistant text in a bounded
  sliding window;
- excludes tool calls, tool output, reasoning, images and encrypted payloads;
- de-duplicates response/event copies of the same message and redacts secrets;
- reconnects and initializes the App Server RPC after an oversized frame closes
  the websocket, before creating or attaching the destination thread.

Regression coverage includes a 40 MiB tool-output record, a simulated 32 MiB
frame disconnect with automatic reconnection, and a read-only parse of the
reported 210 MiB rollout. Provider rebind E2E continues to pass.

Update each installed profile, then restart it:

```bash
curl -fsSL https://github.com/Arginine-Arg/Feishu_bridge_arg/releases/download/v1.21.1/install-global.sh | sh -s -- --version 1.21.1
hash -r
arg-bridge --version
arg-bridge restart --profile codex
```

The existing thread and rollout files are not rewritten by this upgrade.
Re-run the original `--adopt ... --follow-current-provider` command after the
profile restart.
