# arg-bridge v1.18.1

Fixes MixAgents `/btw` and worker turns hanging after a command requests
additional permissions.

The 1.18.0 mailbox reconciliation used the read-only `list_agents` tool. That
detects terminal state, but it does not consume App Server approval or
interaction requests. When Codex printed a message such as “The sandbox is
blocking command execution. Retrying with elevated permissions.”, the approval
stayed pending forever while the Broker continued to report:

```text
status=running
cursor=<unchanged>
```

The observed Pending commandExecution entries were therefore a Bridge/MixAgents
interaction handoff bug rather than proof that the model process had crashed.

Version 1.18.1 calls `wait_agent` with `timeoutMs: 0` every five seconds while a
side is active. This is non-blocking, reconciles the mailbox, and drains pending
command, file-change and other App Server interactions. Permissions that are not
allowed by the existing sandbox policy are declined immediately and returned to
the worker as a tool result, allowing it to continue or fail explicitly instead
of hanging.

The 1.18.0 terminal recovery, 60-second status heartbeat, bounded reasoning
summaries and final-answer de-duplication remain unchanged.

No side migration or `/btw out` is required. Update, restart each bot profile,
then retry the side or use `/btw result`.

Local validation: 1,228 ArgBridge tests passed, 12 environment-dependent tests
skipped, and all 28 vendored Broker tests passed. Type checking, production
build and isolated tarball installation passed.
