# arg-bridge v1.22.0

Fixes native provider switching, stale models and runaway provider recovery.
Also adds ordered subagent provider/model selection with automatic model discovery.

After exiting native, `--bridge <thread-id> --follow-current-provider` now asks
actual idle Bot subscribers to release the target, confirms the Codex writer
lock is free, and resumes the same thread. An exclusive idle retained Server can
be stopped with a targeted SIGTERM; shared/active Servers are preserved. Native
attempts have one cross-profile owner. No writer-lock file is deleted. Failures
identify the known PID/profile and preserve a recoverable thread.

A loaded thread can retain its TUI model even when resume requests another.
Bridge verifies effective resume fields, applies the explicitly requested model
at an idle boundary and verifies the Server result. It preserves thread ID,
history, workspace, frozen permissions and Broker marker.

Provider `willRetry` events no longer inject continue into active turns. Only a
confirmed transient terminal failure can start one new continuation. Recovery
uses one hour per failure episode across automatic turns and restarts, with
30/60/120-second backoff, jitter, Retry-After and persisted deduplication. Budget
expiry stops Bridge submissions and accurately shows whether Codex still runs.
`/recover off|on|status` and `/stop` retain explicit control. Old default infinite
settings migrate to version 2. Details, override configuration and lifecycle
boundaries are in [structured-backend.md](../structured-backend.md#provider-recovery-1220).

Settings can discover authenticated `/models` catalogues for selected cc-switch
providers, let you choose one or two models each and set priority. New dispatches
skip unavailable catalogues, missing models and briefly cooled failed routes.
Catalogue access does not prove inference reliability. Existing worker tasks
are not replayed on another route; keys stay in cc-switch/runtime memory.

Wait deadlines now return pending/still-running, preserve worker handles and
mailboxes, and do not automatically interrupt long training/downloads. Agent
instructions discourage infinite timestamp/sleep loops. Bridge cannot enforce
all commands owned by agent tools and does not kill them by scanning text.

Upgrade the package when convenient:

```bash
curl -fsSL https://github.com/Arginine-Arg/Feishu_bridge_arg/releases/download/v1.22.0/install-global.sh -o /tmp/install-arg-bridge.sh
sh /tmp/install-arg-bridge.sh --version 1.22.0
hash -r
arg-bridge --version
```

New native commands use the updated package immediately. Running Bot processes
need a restart to load new code; wait for an idle boundary before running
`arg-bridge restart --profile codex`. This release does not restart existing
services or experiments for you. During an ongoing task, `/recover off` can
stop old Bridge injections while Codex continues. No re-adopt is needed.

After upgrading, use `arg-bridge settings --profile codex` and choose the new
multiple-provider priority option under subagents. Discovery uses catalogue GET
requests, not paid test completions. Missing catalogue endpoints are clearly
labelled as a local-configuration fallback.

Rollback: disable automatic recovery in the affected conversations/profile
before installing a pinned older release; 1.21.2 otherwise restores its unsafe
infinite-injection defaults. New recovery coordination files are additive and
ignored by old releases. Preserve your profile backups and research history;
never delete a live Codex writer lock to force a downgrade/rebind.

Validation uses mocked/fake providers and local Codex App Servers. Passing these
tests does not claim a real upstream provider became stable.
