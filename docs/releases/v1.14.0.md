# arg-bridge v1.14.0

This release makes side conversations writable by default and makes provider
switching preserve a linear context history.

## `/btw`

```text
/btw <task>
```

The side now defaults to `workspace-write` in the current project. It can run
commands, edit files in that workspace, and use lark-cli to send generated
files back to the current Feishu conversation.

```text
/btw --read-only <task>
/btw --workspace /canonical/descendant <task>
```

`--read-only` explicitly downgrades the side. `--workspace` selects an
authorized canonical path at or below the current project; omitting it uses the
current project. It never means unrestricted disk access.

## Provider lineage

`--adopt <source> --follow-current-provider` now selects the newest thread in
the source lineage:

- switching A -> B -> A creates a new A generation from B's latest context;
- repeating the migration without a newer provider generation remains
  idempotent;
- markers record `previousThreadId` and keep `adoptedFrom` as the lineage root;
- each Bridge-managed thread stores a mode-0600 bounded user/assistant text
  snapshot, merged with newer turns before the next provider migration.

Adoption retains up to 48k characters of recent text. Very large histories use
a recent-turn fallback when full `thread/read` exceeds the RPC budget.

tmux input recovery permits three alternating literal/paste attempts only while
the complete pre-submit screen remains unchanged.
