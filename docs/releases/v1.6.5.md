# arg-bridge v1.6.5

修复"一发消息就报重连"的连续对话中断问题，并按需支持 Node.js 26。

## 结构化传输自愈

之前 App Server 在回合之间退出、被替换或进入 draining 后，bridge 会继续复用它缓存的 RPC 连接，于是**每一条后续消息**都失败：

```
⚠️ agent 失败：Codex App Server connection closed; input will not be replayed
⚠️ agent 失败：Server is draining; retry after reconnecting
```

本次修复：

- **会话存活检测**：缓存的结构化会话在复用前检查 RPC 通道；已关闭的会话会被丢弃，并按保存的 thread 重新连接/恢复，而不是拿死连接继续发消息。
- **draining 孤儿回收**：socket 仍存在但服务已进入 draining（例如包装进程已死、子进程僵着）时，bridge 会终止持有该 socket 的进程、清理运行目录并重新拉起一个可用实例（带一次重试保护）。
- **失效 endpoint 自愈**：绑定或状态里保存的 endpoint 已消失时，不再把 `realpath ENOENT` 抛给用户，而是丢弃该绑定、拉起新的 App Server、用原 thread 续上，并顺带重启该 pane 的原生 TUI。
- **未开始回合的安全重试**：仅当 App Server **明确拒绝**了请求（draining / connection closed / 未连接）且该会话没有任何进行中回合时才重试一次；超时（结果未知）永不重放输入。`/btw` 的 `thread/fork` 同样适用该重试。
- **不再误杀在用实例**：启动/重启时的回收现在会检查 socket 上是否仍有活跃连接（原生 TUI 的 `--remote` 就是一条），有连接就跳过回收；退出时同样只回收空闲实例。`arg-bridge restart` 会打印跳过的数量。
- **杀进程改为杀进程组**：避免"父进程已死、子进程继续持有 socket 并对外报 draining"的半死状态。

## Node.js 26 支持与安装器改进

- `engines` 放宽为 `>=20.12.0 <27`，安装器同步接受 Node 20.12–26。
- 安装器**优先复用兼容的专用运行时**：依次检查 `--node` / `ARG_BRIDGE_NODE`、`~/.arg-bridge/node/bin`、`~/.lark-channel/node/bin`、`~/node/bin`、`~/software/node-v20..26*/bin`，最后才用 PATH 上的 `node`（要求同一目录下有可用的 `npm`）。
- 找不到兼容运行时时**自动部署隔离的 Node LTS**（默认从 nodejs.org 选择最新的 22/24 LTS，可用 `ARG_BRIDGE_NODE_VERSION` 固定版本），下载后校验官方 `SHASUMS256.txt`，解压到 `~/.arg-bridge/node-<version>-<platform>`，因此不再受 Conda/系统 Node 版本干扰。
- **升级失败自动回滚**：安装前备份现有安装与命令软链，npm 安装失败或安装后校验不通过时自动恢复，不会留下半更新状态。

## 验证

- 新增 `tests/unit/agent/rpc-liveness.test.ts`：通道关闭检测、死会话标记、失效 endpoint 判定为类型化错误。
- 新增 `tests/unit/agent/structured-transport-recovery.test.ts`：复现"Server is draining"后重建会话并重发同一回合；以及"已有进行中回合时绝不重试"。
- 新增 `tests/process/codex-app-server-draining.test.ts`：起一个只回 draining 的 App Server，确认 bridge 会回收它并连上健康实例。
- 新增 `tests/unit/agent/host-in-use.test.ts`：有客户端连接时回收被跳过，客户端断开后同一实例被正常回收。
- 安装器实测：PATH 上放 Node 26 假运行时时优先选择 `~/.arg-bridge/node/bin`（输出 `Using Node.js v24.16.0`）；无兼容运行时时自动下载隔离 LTS 并完成安装；用损坏包升级时回滚成功、旧版本命令仍可执行。
- 全量 `pnpm test`：通过；`pnpm typecheck` 通过；`scripts/verify-package-install.mjs` 通过。
