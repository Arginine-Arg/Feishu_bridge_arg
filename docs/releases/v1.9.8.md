# arg-bridge v1.9.8

This release turns `/btw` from a full autonomous-worker invocation into a
dedicated fast side path while keeping automatic subagents independent.

## Web search

- Web search is now selected by provider capability, not by the blanket rule
  that every third-party provider is incompatible.
- `subagents.webSearch=auto` keeps native Responses `web_search` only when the
  provider declares `supports_standalone_web_search=true`.
- `native` force-enables it for a provider verified by the user.
- `disabled` is an explicit policy.
- Settings and `doctor --json` show provider declaration, effective state and
  the reason. Switching to a search-capable provider changes the route
  fingerprint and causes the next `/btw` to use the new capability.

## Fast side path

- `/btw` uses `sideTimeoutMs=90000`, `sideReasoningEffort=low`, and bounded
  Codex request/stream retries.
- Automatic `arg_bridge.*` workers retain `workerTimeoutMs` and the provider's
  normal reasoning configuration.
- The side and worker roles use separate generated configs/data directories, so
  both can run concurrently without sharing an incompatible worker handle.
- A timed-out side is interrupted and reports: switch to a faster
  provider/route or increase `sideTimeoutMs`. The message is never replayed on
  the main model.

## Validation

- Typecheck, build, package installation, unit and process gates pass. The
  complete suite finished with 1155 passing tests and 12 explicit skips.
- A real consecutive `/btw` acceptance completed two rounds on
  `hallong_ds`.
- A real Codex 0.164 request against a local 503 endpoint made four bounded
  attempts and exited in about 1.3 seconds instead of retrying for most of a
  minute.
- Real cc-switch module/provider tests verify that declared-search providers
  keep `web_search`, undeclared providers follow the selected policy, and
  policy changes rotate the route fingerprint.
- Detailed commands and redaction evidence are recorded in
  `docs/smoke-btw-fast-path-1.9.8.md`.
