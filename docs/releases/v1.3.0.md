# arg-bridge v1.3.0

正式发布结构化接口后端；升级后默认仍使用原有终端后端，不会自动迁移或重复运行旧任务。

## 新增

- Codex App Server：结构化文本输入、增量回答、明确的完成事件、按请求 ID 审批和按任务 ID 中断。
- Codex 主线程的原生 tmux 界面连接同一 App Server、同一会话，不额外启动一份模型任务。
- Codex `/btw`：临时分支保留原生 side 边界；准备完成后才提交正文；空正文可进入；`/btw out` 仅中断并退出 side。慢速进入期间的退出会阻止正文继续提交。
- Claude 官方 Agent SDK：支持连续会话、结构化输入、增量转发、审批与中断；已使用 `deepseek-v4-flash` 验证真实连续回复和 tmux 显示。
- 选择回调绑定请求及选项；重连时先恢复输出监听，不把旧选择当作新任务。卡片发送失败时提供可操作的文字选项。
- 不添加 Bridge 自定义系统提示词或额外路由模型。Codex side 仅保留用户已同意的原生边界提示。

## 启用

在对应 profile 的 `preferences` 中设置：

```json
{
  "agentTransport": "structured",
  "structuredNativeView": true
}
```

请在旧任务结束后切换，或使用独立的测试 profile。不要同时启动绑定同一飞书应用的两份 Bridge。

## 已知限制

- 不自动导入旧 tmux 会话；结构化后端尚不支持旧 `/resume`、scope reset 的等价迁移。
- Codex 主界面为原生交互；Codex side 与 Claude 的 tmux 视图当前只读。
- Claude 结构化后端不提供 Codex 的 `/goal`、`/btw`。
- Codex side 生命周期属于当前连接，不承诺 Bridge 重启后的 side 恢复。
- Codex 共享原生终端目前需要 Unix socket 和 tmux；Windows 保留原有终端后端。
- 自定义 Claude 模型请明确设置；只修改 Haiku/Sonnet 映射不会消除冲突的 `ANTHROPIC_MODEL`。

## 验证

发布前检查完整回归、类型检查、构建、跨平台 CI 与 tarball 安装。真实 Codex 测试覆盖普通回复、side 正文/退出，以及主 goal 执行时 side 回答后主 goal 正常完成；真实 Claude/DeepSeek 测试覆盖同一 session 连续两次回复、正常完成、空闲状态及 tmux 最终输出。

测试不能保证零缺陷；详细能力边界见仓库 `docs/structured-backend.md`。可使用安装脚本的 `--version 1.2.7` 回退包版本，并将 profile 的 `agentTransport` 恢复为 `terminal`。
