# arg-bridge v1.11.1

This release fixes the interaction between a bounded waiting policy and
long-running Broker work.

## Soft and hard budgets

- `sideTimeoutMs` is now a soft notice for read-only `/btw`.
- The side keeps running after that notice. Each `workerTimeoutMs` wait window
  automatically rolls into another window until completion or `/btw out`.
- Streaming text/tool progress continues during the extended wait.
- A wait-window boundary no longer interrupts or terminates the side.

## Late result collection

- Added `/btw result` as a recovery path for retained timeout state from older
  versions, Bridge interruption or abnormal lifecycle recovery.
- It resumes `read_agent_events` from the persisted cursor without replaying the
  original task.
- If the result is ready, the final mailbox answer is delivered normally.
- If it is still running, the side remains retained and `/btw result` can be
  repeated.
- A normal new `/btw` cannot silently replace a retained timeout side. The user must
  collect it with `/btw result` or discard/interrupt it with `/btw out`.

## Diagnostics

- `/status` reports the side agent status and progress cursor.
- Retained-state diagnostics point to `/btw result` and `/btw out`.
- Settings labels now describe `sideTimeoutMs` as a fast waiting notice rather
  than a maximum execution time.

## Validation

- Tests cover automatic wait-window continuation, timeout-state retention, `/btw result`
  cursor resume, duplicate-answer prevention, explicit discard behavior and the
  requirement to resolve a retained timeout side before starting a new task.
- Local full gate: 1,175 ArgBridge tests plus 27 vendored Broker tests passed;
  11 environment-dependent tests skipped.
- Package preview is approximately 516 KiB, only about 0.5% above v1.11.0.
