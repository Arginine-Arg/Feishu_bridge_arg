# arg-bridge v1.5.5

增加 structured 优先、原生 live 回退和当前 shell 启动入口。

- profile 的 `full` 权限映射为 App Server 的 `danger-full-access + approvalPolicy=never`；`workspace` 和 `read-only` 也在 thread、turn、remote TUI 三条路径保持一致，不再把结构化新会话硬编码成 `read-only + on-request`。
- 共享 tmux TUI 使用同一个 App Server/thread，并携带对应权限参数；Bridge 与 tmux 不会启动第二个模型任务。
- `/tmux bind` 绑定实际运行的 pane：有共享 endpoint 的 Codex 使用 structured；普通 Codex/Claude 使用该 pane 的 live。不会为正在运行的普通 Codex 另起 App Server writer。
- 新增 `arg-bridge native [thread-id] --profile codex`：在当前 shell 的环境中启动共享 App Server/TUI。可以先执行 `clash on`，退出 Codex 后回到原来的 shell，不必手工创建 socket 或新 pane。
- `arg-bridge native [session-id] --profile claude` 打开原生 Claude，绑定后使用 live；未绑定的 Claude structured 会话继续使用 SDK。
- 按指定 pane 的实际进程识别 thread/endpoint；不再使用旧启动字符串，不随其他 pane 的选中状态漂移。退出到 shell 后保留绑定，并拒绝向缓存的旧 thread 发送消息。
- 回退只在提交前选择。已发送后出现超时或结果不明，不会换后端重发。
- remote Codex 退出后保留交互式 shell，便于重新执行 `clash on`、检查环境或再次 resume；Bridge 不会因一次 Ctrl-C 自动杀掉 tmux session。
- shell 中没有 agent 时需手动运行上述启动入口；Bridge 不清空 shell 的输入行、不注入启动命令。已经运行的 App Server 不会追溯继承后来执行的 `clash on` 环境。

默认 workspace、profile 配置和现有 terminal 后端均不改变。
